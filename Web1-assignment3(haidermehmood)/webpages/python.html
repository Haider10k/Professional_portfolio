User Validation Program

What is it?

This project is a Python-based validation program designed to control access to a system by checking both the username and IP address of a user. The program compares each login attempt against two external files: one containing a list of denied users and another containing denied IP addresses. If either the username or IP address appears in the restricted lists, the program displays a message in the terminal denying access. If both checks pass, the user is granted access and their information: username and IP address is recorded in a separate file for approved entries

Tools used

Python was the core language used to build the validation program, handling all logic, comparisons, file operations, and decision-making. It allowed the application to read and process user input, verify credentials against external files, and determine whether access should be granted or denied.

  • Using conditional logic to approve or deny access
  • Reading and validating usernames from a denied users file
  • Comparing IP addresses against a list of blocked IPs
  • Writing approved user data into a separate output file
  • Handling program flow through input prompts and printed responses
  • Ensuring clear feedback messages for accepted or denied access

Development Process

I developed the program by first creating simple file-reading functions to load usernames and IP addresses from text files. From there, I built the core validation logic, starting with username checks and then expanding it to include IP address verification using the same step-by-step process. Once both checks worked together, the program became a complete access-control system that could approve or deny users based on external data. I plan to continue improving this project by adding a visual interface and introducing different access-level permissions in the future

Obstacles Encountered

A key challenge in developing this program was separating and correctly interpreting the different data formats stored in the external files. Some entries contained only a username, while others included both a username and an IP address, and the program needed to distinguish between the two to avoid incorrect validation results

How it was Solved

This required restructuring the logic so that each case: user-only data and user-plus-IP data was processed separately, ensuring that comparisons were accurate and the program executed correctly
